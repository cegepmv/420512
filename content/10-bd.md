## 1. Introduction à `expo-sqlite` (API Synchrone)
Depuis les versions récentes d'Expo, `expo-sqlite` intègre des méthodes synchrones (`openDatabaseSync`, `execSync`, `getAllSync`, `runSync`). 

* **Avantage principal :** Simplifie la gestion du flux de données en évitant les promesses/callbacks (`async`/`await`) au moment de l'initialisation et des requêtes simples.

---

## 2. Architecture & Séparation des Responsabilités

Il est préférable de séparer la logique de persistance des données de la vue (UI).

``
├── services/
│   └── database.js  <-- Gestion DB (initialisation + requêtes SQL)
└── app/
    └── index.jsx    <-- Interface utilisateur (React Native + State)
``

---

## 3. Le Service Base de Données (`database.js`)

### A. Ouverture et Initialisation
``javascript
import * as SQLite from 'expo-sqlite';

// Ouverture synchrone (crée le fichier s'il n'existe pas)
export const db = SQLite.openDatabaseSync('todo_db.db');

// Création immédiate de la structure
db.execSync(`
    CREATE TABLE IF NOT EXISTS tasks (
        id INTEGER PRIMARY KEY AUTOINCREMENT,
        text TEXT NOT NULL
    );
`);
``
> **Remarque :** L'exécution de `execSync` à la racine du module garantit que la table `tasks` existe déjà lors de l'import dans les composants.

### B. Abstraction des Requêtes (Fonctions Helpers)
Pour ne pas répéter le code SQLite dans l'UI, on exporte deux wrappers génériques :

``javascript
// Récupération de données (SELECT) -> Retourne un tableau d'objets
export const queryAll = (sql, params = []) => {
    return db.getAllSync(sql, params);
};

// Modification de données (INSERT, UPDATE, DELETE) -> Retourne le résultat de l'exécution
export const runQuery = (sql, params = []) => {
    return db.runSync(sql, params);
};
``

## 4. Intégration dans l'UI (`index.jsx`)

### A. Chargement initial (`SELECT`)
Au montage du composant (`useEffect`), les données sont lues en BD pour initialiser le `state` React.

``javascript
const [data, setData] = useState([]);

useEffect(() => {
    loadTasks();
}, []);

const loadTasks = () => {
    const allRows = queryAll('SELECT * FROM tasks;');
    setData(allRows); // Met à jour l'état local avec les lignes de la DB
};
``

### B. Insertion Sécurisée (`INSERT`)
L'utilisation de **requêtes préparées** (avec le joker `?`) protège contre les **injections SQL**.

``javascript
const handlePressPlus = () => {
    if (textInput.trim() === '') return;

    // Transmission sécurisée via le tableau de paramètres
    runQuery('INSERT INTO tasks (text) VALUES (?);', [textInput]);
    
    setTextInput('');
    Keyboard.dismiss();
    loadTasks(); // Rafraîchit l'UI
};
``

### C. Suppression (`DELETE`)
``javascript
const handleDelete = (id) => {
    runQuery('DELETE FROM tasks WHERE id = ?;', [id]);
    loadTasks(); // Rafraîchit l'UI après suppression
};
``

---

## 5. Interaction UI (`Swipeable`)
La suppression est déclenchée lors du glissement d'un élément grâce à la propriété `onSwipeableWillOpen` du composant `Swipeable` (`react-native-gesture-handler`).

``javascript
<Swipeable renderLeftActions={afficheText} onSwipeableWillOpen={() => handleDelete(item.id)}>
    <View style={styles.task}>
        <Text style={styles.taskText}>{item.text}</Text>
    </View>
</Swipeable>
``

## 💡 Résumé des points clés

1. **Sécurité SQL :** Ne JAMAIS concaténer les variables directement dans la chaîne SQL. Toujours utiliser les marqueurs `?` et passer les valeurs dans le tableau `params`.
2. **Cycle de vie & Synchro :** SQLite gère la persistance sur disque. Pour refléter les changements sur l'écran, il faut explicitement relire la base et recharger le state React (`loadTasks()`).
3. **Clé primaire (`PRIMARY KEY AUTOINCREMENT`) :** Assure un identifiant unique `id` par ligne, indispensable pour alimenter `keyExtractor` dans les `FlatList` et cibler la bonne ligne lors d'un `DELETE`.
